# Assumptions, inconsistencies, and reproduction risks

Status: proposals for review, not approved implementation settings. No assumption below has been implemented. The source is [MFVLR.pdf](../papers/MFVLR.pdf); page numbers refer to that file. **EXPLICIT** means a paper statement, **DERIVED** means an inference with its premises, and **ASSUMED** means a required choice that the paper does not settle. A proposed default does not become a paper fact when selected.

The paper specifies a recognizable architecture but not a unique executable network or training protocol. A reproduction can preserve the published graph and document decisions; it cannot honestly claim to recover undisclosed author settings. In particular, scalar losses require interpretation, and exact numerical replication requires dataset/split/training details absent here.

## Decision register

Priority: **critical** affects the mathematical objective, architecture or data integrity; **high** materially affects performance or replication; **medium** affects execution or reporting. “Open” means review is still required before calling the resulting run a settled reproduction. Candidate defaults are **ASSUMED** throughout.

## Choices that would change the method

The following are **ASSUMED extensions**, not faithful resolutions of missing details:

- Replacing learned appearance reconstruction with a pretrained diffusion reconstructor, DIRE error, SRM/noise filters, Sobel or FFT features (conflicts with §III-B p. 5).
- Loading pretrained CLIP, U-Net, SAM or other backbone weights (conflicts with §II-B p. 4).
- Giving VIM patches or multiple synthetic visual tokens in the default model, swapping its softmax axis to force nontrivial attention, or silently correcting Eq. (10)'s scale (conflicts with p. 7; patch variants only appear as ablations).
- Untying IE/RE or AD/MD trunk weights, concatenating their global vectors, or using a learned fusion gate (conflicts with §§III-B/C pp. 5–6).
- Adding hidden layers to the detection/adapter heads, independent output vocabulary weights, extra loss weights, Dice/focal losses, positive-pair class grouping or a language teacher (not specified in pp. 7–8).
- Detaching the residual, training reconstruction only on real images, introducing staged pretraining, corrupted-text denoising or target-free language generation (not specified; modifies the dependency or objective assumptions).
- Passing ground-truth hierarchy prompts, source images or labels during inference, or removing AD while retaining claimed original detection behavior (conflicts with §III-A p. 4).

Loss softmax interpretation and scalar reductions are different: they are necessary to make the published notation executable, but still must be named and reported. A mathematically conventional repair is not automatically an explicit paper requirement.

## Review priorities before implementation

The following is a prioritized review list, not a request that interrupted the documentation work.

1. Set the baseline's equation interpretation: singleton VIM and printed scale (A12), single residual ownership (A13), categorical log-softmax interpretation and scalar reductions (A17/A18), raw dot versus cosine CMC (A14), KL gradient/temperature and learned-temperature parameterization (A15/A19).
2. Select an explicit U-Net/block definition and all hidden dimensions/normalizations (A02–A05), keeping these settings visibly assumed.
3. Resolve tokenizer packing, EOS/padding, final-token pooling and decoder shift (A08–A11). No guessed 77-token packing should pass as recovered author intent.
4. Establish source-pair mask preprocessing, available dataset split manifests, source-domain validation and training duration (A01/A21/A23).
5. Freeze metric conventions and a comparison protocol, then assess main results before spending resources on underspecified secondary ablations (A24–A34).

Author clarification or additional primary-source material could resolve some items. None is required to finish these research documents, and no external contact has been made. The current deliverable stops here for review as requested.
